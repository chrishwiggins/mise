## What these classes mean for the migration

Generated 2026-09-05 for doc/plan-tcsh2bash.md step 2. Every count here was
produced by running `py/alias-census`, which resolves each alias's target
inside a real tcsh with the login chain and the alias file itself sourced.

- LIVE (256): target resolves to something that exists. The translation surface.
- CHAIN (36): target is ANOTHER alias in the same file. Real and working, but
  the migration has to translate the target first, so these are ordered after
  whatever they point at.
- SHELL-ONLY (16 direct): the body calls cd, setenv, set, source, history or
  alias, which act on the calling shell. A script cannot do these for its
  parent. These become shell functions, never scripts.
- SHADOWED (16): an earlier definition of a name that a later line redefines.
  tcsh keeps only the last, so these lines have never been reachable. Retire,
  never translate.
- DEAD (11): target does not exist. All 11 were hand-verified independently of
  the tool, against both alias files. Retire.

TRUE SHELL-ONLY TOTAL IS 23, NOT 16. Seven CHAIN rows point at an alias whose
own body is shell-only, so they inherit the property transitively: dusort (58,
source), miseup (113, cd), remise (115, cd), d (134, setenv), pu (223, cd),
uppu (478, cd), cd-f (541, cd). Any of these that is translated to a script
will silently fail to change the caller's directory, which is the same class of
silent failure that started this project.

The 11 DEAD, all verified gone: jsc (57), gv (136, smail), json-grep (158,
jgrep), conda-tend (191, conda), pwstore (197, /opt/homebrew/bin/pass), st2
